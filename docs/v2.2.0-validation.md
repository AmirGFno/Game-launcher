# GFno Launcher 2.2.0 — implementation and acceptance

Built on the merged 2.1.3 tree, without reset or architecture migration. Native .NET 10 WPF/WinForms; ImageSharp 3.1.12 and custom logos retained. No tag, merge or release authorized by this implementation request.

## Implementation

- Fullscreen uses CanMinimize, hides the custom maximize button and ignores maximize/title-bar double-click/drag. Leaving fullscreen restores normal resizable min/max/close behavior. F11 remains an explicit fullscreen-setting toggle.
- Both edge bars use one visibility state, one 400ms hide deadline, and 150ms snapshot-and-replace opacity/translation animations. A timer tick does not restart an in-flight animation. Either edge or hovering either bar keeps both visible.
- All launches hide ChromeRoot (including spinner) before process start. A background task holds the Process.Start reference and observes readiness; only then does the window minimize to the taskbar by default (a separate persisted “Minimize to tray after game launch” setting opts into hiding). No launch path exits the launcher. Failure restores chrome before the error dialog. Taskbar/tray return restores UI.
- Direct executables: started PID window or sustained liveness, verified Toolhelp ancestry while parent identity remains live, then exact executable path + recent creation time fallback. Bounded 12-second wait; unconfirmed exited stubs restore UI with an error. Some very fast bootstrap parents can exit before ancestry is sampled; this is intentionally not treated as authority to close arbitrary processes.
- Steam: AppID Running registry state and recent process paths under the manifest install directory; metadata is retained in local JSON. After an 8-second grace without confirmation the launcher yields the screen anyway (not a claim the game started), so Steam dialogs cannot remain covered for 60–90 seconds. Observed Steam processes are not cleanup-owned.
- Clean keeps the existing product-owned `%LocalAppData%\GameLauncher\Cache` scope; it does NOT clear the global Windows TEMP folder. Confirmation mentions process closure even when cache is empty. It requests graceful close only for session-owned PID/start-time/executable identities, including verified descendants. Steam is always excluded. No forced kill/elevation; unresponsive/headless processes are reported skipped. Automatic prelaunch cache cleanup does not close processes.
- Nested deletion and preview avoid reparse points; locked child files are traced and do not prevent siblings from being cleaned. Counts are top-level cache entries, not individual nested files. The cache root is never deleted.
- Loop: named 90px strip-top offset (46px lower than 2.1.3), selected scale 1.28, 18px title tied to tile position/scale with the same 300ms easing, extra selection breathing room, strong half-edge dissolve and right reserved slot. Fixed: opacity mask is null, white selected glow retained. Scale remains RenderTransform only.

## Steam defects found and addressed

1. Re-import used File.Exists, so empty/corrupt artwork prevented repair. Existing files are now decoded/validated before deciding to skip.
2. Corrupt unmarked stable files collided with the downloader's manual-file protection, causing every fallback to fail. A stable `_repaired` cache filename allows repair without deleting or overwriting the legacy/manual file; repaired cache is reused.
3. Host-major retries could spend many minutes on one broken host. Filename-major retries rotate hosts, with a 5-second attempt deadline and 40-second per-artwork budget. Logo and hero run concurrently. Ordinary editor downloads retain their 30-second limit.
4. Inaccessible libraries/VDF could abort discovery of otherwise readable libraries. Read failures now preserve local manifest discovery where possible.
5. Installed directory was not retained for launch detection. Safe descendant install paths from manifests are persisted, including re-imports.
6. Replaced stable image files could retain stale decoded cache entries. Successful promotion invalidates the shared image cache; existing import-finally carousel/background refresh is preserved.

The shared downloader retains browser User-Agent/Accept, decompression, HTTP status and non-empty body checks, size/dimension limits, content-based decode validation and closed `.part` atomic promotion. HTML is rejected regardless of its advertised Content-Type. Real CDN success is NOT claimed: the sandbox cannot reach Steam hosts. Slow CDN responses can exceed the deliberately bounded attempt budget; a later re-import retries missing art.

## Automated validation

No local dotnet or interactive Windows desktop is available. Run on Windows CI:

```text
dotnet build GameLauncher.csproj -c Release --nologo -v minimal
dotnet test tests/GFnoLauncher.Tests/GFnoLauncher.Tests.csproj -c Release --nologo -v minimal --logger "trx;LogFileName=results.trx" --results-directory TestResults
```

Coverage includes offline HTTP 403→200 fallback through the actual downloader, malformed body rejection, WebP decode, corrupt-cache repair/reuse, launch preparation/readiness/minimize ordering, bounded polling/cancellation, STA carousel masks/scale/style switching, nested junction protection, locked sibling cleanup and existing metadata/tray/path tests. Final CI run/count is recorded in PR #25; process-observation heuristics still require real-game acceptance.

## Manual Windows checklist — not performed in sandbox

- Fullscreen: only Minimize and Close; double-click header cannot restore down. Exit fullscreen via Settings/F11 and verify min/max/close, resizing and dragging.
- Move to top OR bottom 10px edge: both bars reveal together. Hover either bar, then leave: both hide after ~400ms, without repeated animation lag. Repeat rapidly.
- Launch EXE and Steam in fullscreen/windowed mode: immediate background-only presentation, no overlay; launcher stays alive, then minimizes/hides after readiness/grace. Verify direct stub/child launch, already-running game, slow Steam startup, failure and cancellation.
- Return via taskbar/tray/single-instance activation: normal chrome, input and edge reveal work again; no stuck launch flag.
- Real multi-library Steam scan/manual folder: titles/install metadata/images appear, re-import skips valid images, corrupt cache repairs, 403/offline/missing art imports without crash. Check all three hosts on a real network.
- Loop: lower strip, larger selected tile, smaller attached animated name, no orphan animation after rapid direction changes, strong half-edge dissolve, empty right slot; test 1/3/6/20 games and 100/150/200% DPI.
- Fixed: no edge dissolve, white selected-only glow, centered top title; switch styles repeatedly.
- Clean: cancel confirmation changes nothing; confirm cleans only app cache and requests close on owned processes. Verify unrelated apps/Steam survive, locked files and unresponsive processes are reported skipped, manual artwork/library remain.
- Add/edit/delete, PNG/JPG/ICO/WebP local/download previews, metadata/unknown JSON fields, settings persistence, Close to Tray versus Quit and second-instance restore.

ImageSharp 3.1.12 retains known upstream advisories as requested. No claim of upstream vulnerability remediation or GA readiness.

# GFno Launcher 2.1 development status

## Distribution

- PR #22 remains open on `arena/541a76c4-game-launcher`.
- The existing `v2.1.0` prerelease is immutable and predates the latest theme and reliability changes. It is not the current branch build.
- Current Windows preview ZIP and installer packages are uploaded by PR CI as `GFnoLauncher-2.1.0-preview`. These contain packaged React assets and require WebView2 Runtime, not Node.js or a development server.
- v2.0.0 remains the stable release. No stable promotion or PR merge has been performed.

## Implemented

- React/TypeScript frontend hosted by WebView2 in the existing WPF project layout.
- Minimalist full-screen artwork, small selected-game title, and a carousel whose selected tile left edge is fixed at 340px: two 140px slots plus 30px gaps. Track movement uses the requested transform easing.
- Navy, turquoise and lavender palette; existing saved accents remain respected.
- Library navigation removed at user request. Top-right Performance modal beside Add. Frosted bottom hints with edit/delete and persistent reorder controls.
- Game editor, executable picker, launch profiles, artwork file selection, image downloads and explicit metadata detection (draft-only until Save).
- Closed asynchronous bridge dispatch, correlation, source/origin checks, navigation restrictions and CSP.
- Serialized bridge transactions, preserved LastPlayed/LaunchCount on edits, successful-launch metadata updates.
- Process CPU-time/working-set sampling and Windows GetSystemTimes system CPU measurements.
- Session history updates launch records with observed durations rather than duplicating them. Shutdown drains queued history writes; switching monitored games finalizes the previous observation.
- Duplicate requests blocked while the selected game is monitored as running/waiting, plus a short repeat-click cooldown.
- Single-instance activation now uses a per-user, per-session signal to restore the hidden tray window instead of searching only visible process windows.

## Still required before stable delivery

- Interactive Windows verification: real executable and Steam launches, runtime rendering, tray restore, shutdown, persisted settings, image corruption handling, and upgrade/uninstall behavior. Automated compilation and packaging are not substitutes for these checks.
- Safe startup preparation UI, protected-application policy and cancellable graceful-close flow. Do not expose unrestricted closing as an optimization feature.
- Stronger detection of already-running games when monitoring is disabled or games were started externally; store launches without a configured process cannot be inferred reliably.
- System measurement warm-up/unavailability presentation and startup preference failure reporting.
- More frontend interaction/accessibility tests, monitoring lifecycle and Windows integration tests.
- Review ImageSharp 3.1.12 advisory exposure; no paid licensing requirement or unrelated dependency upgrade has been introduced.

## Browser preview

Run `npm ci`, `npm run build` in `frontend`, then serve `frontend/dist`. Browser mode deliberately cannot access the Windows library or fabricate measurements. Build the frontend before building the desktop project; MSBuild copies assets to output/publish `wwwroot`.

# GFno Launcher 2.1.3 — implementation and validation

Native C# / .NET 10 / WPF + WinForms, based on the existing v2.1.2 branch. ImageSharp remains 3.1.12. User icons, storage paths, asInvoker, launch validation, JSON metadata preservation, tray activation and async image fixes are retained. No web architecture, tag, release or main-branch push is part of this update.

## Source changes

- `Controls/GameCarousel.cs`: complete dual-layout implementation, immediate selected title and interruptible presentation-value animations. No `_moving` queue or completion-based selection. Loop uses 120px square tiles / 10px gap, third-slot anchor, bottom-right title, reserved right slot, edge mask, CubicEase-out and no effects. Fixed uses 140px tiles / 15px margins, centered heading and selected-only white glow with QuarticEase-in/out. All scaling is RenderTransform.
- `MainWindow.xaml(.cs)`: common 300ms transition timeline, generation-protected background loads, fullscreen edge bars with delayed hiding, and background-only launch presentation. A cold decode can finish after the transition deadline; the current target then replaces the background immediately, never an obsolete request. This cannot make disk decoding instantaneous.
- `Services/ImageDownloader.cs`: shared decompression-capable HTTP client, browser headers, streamed-body timeout/cap, content-derived extensions, decode validation, and atomic `.part` promotion **after the writer is closed**. The previous exclusive write handle prevented reopening the file for validation on Windows. Expected failures reach the existing editor error dialog; Steam falls back and reports missing artwork.
- `Converters/ImageLoader.cs`: ImageSharp content sniffing for all non-ICO formats, target-sized first-frame decode, dimension/file caps and frozen WPF bitmap conversion. ICO remains on the native WPF decoder. This covers WebP with misleading suffixes as well as `.webp` files.
- `Services/SteamScannerService.cs`: ordered three-host fallback lists, stable AppID cache names, validation before cache reuse, missing-art repair without replacing existing manual art/metadata, and AppID duplicate detection.
- `Views/MenuStyles.xaml`, Settings and Editor: native dark cards, keyboard focus/hover states, scrollable layouts, all previous capabilities retained, local artwork previews through AsyncImage, and renamed Loop Style.
- `Services/ArtworkCacheService.cs`: only explicitly tracked download files are cleared, never arbitrary manual artwork. Older unmarked images are conservatively retained.
- Version is 2.1.3 in project, manifest and installer. No runtime/dependency upgrade.

## Automated validation

Executed on Windows GitHub Actions because the sandbox has no .NET SDK:

```
dotnet build GameLauncher.csproj -c Release --nologo -v minimal
dotnet test tests/GFnoLauncher.Tests/GFnoLauncher.Tests.csproj -c Release --nologo -v minimal --logger "trx;LogFileName=results.trx" --results-directory TestResults
```

Tests include live STA WPF animation/binding, immediate rapid-selection titles, glow rules, native menu resource loading, settings migration, fullscreen launch ordering/success/failure restoration, fake-HTTP downloads, format sniffing, WebP decoding, Steam fallback/cache reuse and total failure. Final run result is recorded in the PR and completion report; do not infer a pass from this checklist.

## Manual Windows acceptance checklist (not performed here)

- Rapid Left/Right and mouse-wheel navigation: verify newest title/tile/background, both wrap directions, no queued lag; test a cold image cache as well as a warm cache.
- Loop Style: third-from-left selection, square icons, 120/10 geometry, title bottom-right, edge fades, right empty slot, no glow, no overlap at 100/150/200% DPI and different window widths.
- Fixed Anchor: original-like 140/15 proportions, center-top heading, selected-only white glow, no clipping when scaling.
- Steam scan on a real installation with multiple libraries: verify actual artwork files, host fallback, AppID deduplication, retry of missing art and cached reuse; cancel mid-download and test offline operation.
- Editor: browse/download PNG, JPEG, ICO and WebP; verify preview, carousel and background after Save/restart. Try a WebP served from a `.jpg` URL, HTML error pages, 403, empty responses and invalid images.
- Inspect Settings/Editor card layouts and keyboard tab/focus; confirm all settings persist and legacy names load.
- Fullscreen: only the relevant edge bar reveals, stays clickable, then hides; neither bar blocks carousel navigation. Check multiple-monitor DPI and F11 geometry restoration.
- Fullscreen executable/Steam launch: all UI and overlays disappear, selected game's background stays, launcher yields to game; failure restores UI before error. Edge reveal must stay disabled during launch.
- Non-fullscreen launch unchanged; metadata still saved; launching never requests elevation.
- Tray hide/show, second-instance restore, Close to Tray vs Quit on Close, normal quit.
- Cleanup defaults off; enable only app-cache cleanup, verify locked files are skipped and junctions rejected. Artwork clear must keep library/manual images and unmarked legacy files.

## Known limitations

- Real external CDN access is blocked by sandbox network policy; only fake HTTP and Windows CI decoding tests are executable here.
- UI smoke tests are not a substitute for real Steam/game focus and multi-monitor acceptance testing.
- ImageSharp 3.1.12 has previously documented advisories; it is retained as instructed. No claim that those upstream vulnerabilities were fixed.
